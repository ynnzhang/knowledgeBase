# 知序 · 本地知识库

支持 macOS 和 Windows；两端共用启动、笔记编辑、图片、目录管理和飞书同步逻辑。

## Windows 启动

1. 安装 Node.js 22.13 或更高版本，安装时保留加入 PATH 的选项。
2. 双击项目中的 `启动知识库网站.cmd`。首次启动会自动安装依赖；网站和编辑服务就绪后自动打开浏览器。
3. 已有 `E:\Note` 时继续使用该目录；否则使用用户主目录下的 `Note`（例如 `C:\Users\你的用户名\Note`），首次启动会自动创建。也可以点击网页中的文件夹图标选择已有笔记目录。

启动后保留窗口，按 **Ctrl+C** 停止本次启动的服务；Windows 如询问是否终止批处理，输入 `Y`。搜索使用 **Ctrl+K**，编辑保存使用 **Ctrl+S**。

## macOS 启动

1. 安装 Node.js 22.13 或更高版本（Apple Silicon 和 Intel Mac 均可）。
2. 双击项目中的 `启动知识库网站.command`。首次启动会自动安装依赖；服务就绪后自动打开浏览器。
3. 将 Markdown 笔记放在用户主目录下的 `Note` 文件夹（`~/Note`）。首次启动会创建该文件夹，文件修改后自动同步。

启动后保留终端窗口；按 **Control+C** 或关闭窗口停止本次启动的服务。Mac 中搜索使用 **⌘K**，在编辑区保存使用 **⌘S**。

如果 Finder 提示没有执行权限，在项目目录打开终端运行：

```sh
chmod +x 启动知识库网站.command
./启动知识库网站.command
```

两个系统也都可以在项目目录运行 `npm run local`，自动安装依赖并在就绪后打开浏览器。开发时可运行 `npm ci`，然后运行 `npm run dev`，手动访问 http://localhost:3000/。PowerShell 若限制运行 `npm.ps1`，使用 `npm.cmd run local`。

## 指定笔记目录

复制 `.env.example` 为 `.env.local`，取消 `KNOWLEDGE_BASE_PATH` 行的注释并填写已有目录，例如：

```dotenv
KNOWLEDGE_BASE_PATH="~/Documents/我的笔记"
KNOWLEDGE_BASE_API_PORT=4312
```

支持中文、空格、`~/` 和相对于项目目录的路径。自定义目录需要提前创建。配置修改后重启服务；终端环境变量优先于 `.env.local`，其次是 `.env`。

Windows 示例（建议使用正斜杠，也支持盘符反斜杠路径、`~\` 和 UNC 共享目录）：

```dotenv
KNOWLEDGE_BASE_PATH="D:/我的 笔记"
KNOWLEDGE_BASE_API_PORT=4312
```

在 Windows 和 Mac 之间迁移时，复制整个笔记目录（含图片、`.assets` 和 `.zhixu-feishu` 子目录），再通过网页重新选择笔记目录。笔记中的相对图片路径支持正斜杠和反斜杠。网页编辑会直接保存到本地 Markdown 文件。

不要跨系统复制 `node_modules`、`dist`、`.next`、`.vinext`、`.wrangler` 等依赖或生成目录；在目标电脑运行 `npm ci` 安装对应平台的依赖。`.knowledge-base.local.json` 记录的是单台电脑的绝对路径，也不要随项目迁移；若已复制，可删除这个配置文件后重新选择目录（不会删除笔记）。

## 常见问题

- 找不到 Node.js：Windows 检查 Node.js 和 npm 是否已加入 PATH，安装后重新打开窗口；Mac 启动入口还会检查 Homebrew 的常见安装位置及默认 nvm 安装。其他版本管理器可在其已配置的终端运行 `npm run local`。
- 端口占用：网站使用 3000，编辑服务默认使用 4312。关闭已有服务，或修改编辑服务端口后重启。两个系统重复双击启动文件都会复用同一项目、同一目录的已运行服务。
- 无法读取笔记：检查 `.env.local` 路径和目录权限；macOS 询问终端访问文稿或桌面文件夹时，允许访问所选笔记目录。
- 启动提示 `Cannot find module .../scripts/local-config.mjs` 或「项目文件不完整」：说明项目源码没有复制齐，不是 Node.js 版本问题。完整解压同一版本的项目包，或从原电脑同步完整的 `scripts/`、`app/`、配置和依赖清单；不要只补一个文件。`npm install` / `npm ci` 不能补回项目源码。新版启动器及 `npm run dev` 会在启动服务前列出缺失文件，也可单独运行 `npm run check:project`。
- 将项目通过 Git 传到另一台电脑时，原电脑的新增源码必须先纳入提交；仅复制 Git 已跟踪文件或仅执行 `git pull` 不会带上未提交的新文件。通过项目包迁移时建议解压到新的项目目录，在 Windows 上重新安装依赖。保留 Windows 原有的笔记目录；按需迁移本机 `.env.local`、`.feishu-local.json` 和 `.knowledge-base.local.json`，不要用 Mac 的绝对路径配置覆盖它们。
- 不想自动打开浏览器：Mac 运行 `ZHIXU_NO_BROWSER=1 npm run local`；Windows PowerShell 先运行 `$env:ZHIXU_NO_BROWSER='1'`，再运行 `npm.cmd run local`；CMD 先运行 `set "ZHIXU_NO_BROWSER=1"`，再运行 `npm run local`。

## 本地验证

点击左侧标题旁的小文件夹图标（悬停提示「打开本地文件夹」）会打开电脑的系统目录选择窗口，选中后直接将该目录作为知识库，自动监视和保存其中的笔记。当前路径显示在图标的悬停提示中；系统选择器无法打开时，可在错误提示中输入绝对路径。最近选择的目录保存在项目的 `.knowledge-base.local.json` 中，重启后继续使用，优先于环境变量中的初始目录；该文件不会提交到 Git。选择新目录不会复制或删除原目录中的笔记。

左侧支持「新建笔记」「新建文件夹」，文件和文件夹均可直接拖到目标文件夹，也可拖到左侧顶部的「知识库 / 文件」路径栏以移至根目录；只有拖拽时才显示目标提示与高亮。移动文件夹会携带全部子目录与附件，修正 Markdown/HTML 中的相对图片链接和笔记链接，并保留飞书关联。同名冲突、拖入自身或子目录、未保存内容或同步进行中会阻止操作。移动只改变本地位置，不会移动飞书上的文档。

正文打开后即可直接编辑，无须切换查看/编辑模式。输入后自动保存；选中文字右键可设置加粗、斜体、删除线、行内代码、正文、1–6 级标题及引用。支持 Markdown 输入快捷方式和 **⌘/Ctrl+B**、**⌘/Ctrl+I**、**⌘/Ctrl+S**。

点击文件只打开笔记，左侧继续保留文件列表；需要时手动点击「大纲」，按正文的 1–6 级标题缩进显示；点击标题跳转到相应章节，滚动正文时高亮当前章节。标题修改后实时更新，同名标题也可分别定位。点击「文件」切回目录树；搜索或筛选标签时自动显示文件列表。手机上可通过顶部展开目录按钮打开左栏，再点击大纲标题回到正文。没有标题时显示添加标题的提示，代码块中的 `#` 不会被当作标题；原文编辑模式下支持定位并选中标题。

搜索框旁的目录图标可收起或展开左栏，页面会记住选择，当前笔记和编辑内容不会因收起而重置。文件和文件夹支持右键「重命名」或聚焦后按 **F2**；重命名会更新附件与链接、保留飞书关联。正文标题旁的小页宽图标展开连续滑块，平时隐藏调整控件。

右键笔记可选择「删除」，确认后移入知识库的 `.trash/<操作编号>/`，列表自动刷新；此功能仅删除单个 Markdown 文件。图片附件和飞书原文保留，本地飞书关联解除，其他笔记指向它的链接可能失效。需要恢复时，按同目录 `manifest.json` 的 `path` 将笔记移回原位置（不要覆盖已有同名笔记）；恢复文件不会自动恢复飞书关联。`.trash` 是知识库内的隐藏目录，不是系统回收站，macOS 可按 **⌘⇧.** 显示，Windows 可在资源管理器开启「隐藏的项目」。保存或同步期间暂不可删除。

界面只保留目录和笔记名称，不再显示列表信息列、文件夹计数和常驻同步提示。右上角的小标签图标集中提供当前笔记加标签、全库标签重命名/合并与移除、按标签筛选。多选标签时匹配全部所选标签，可在同一弹层清除筛选；图标上的小圆点表示筛选已启用。标签管理只修改元数据，保留笔记正文和飞书关联，并在本地保存操作备份。正文自动保存，也可按 **Control+S / ⌘S**，无需保存按钮。

运行 `npm run test:local` 检查目录解析、文件监视、保存、图片读写、本地目录切换与重启记忆、新建与拖拽移动所用的文件接口、链接修复和冲突保护。测试使用临时笔记，不会修改实际知识库。

## 飞书手动同步

重启本地启动程序后，点击网页右上角 **飞书同步**。仅在本地开发服务（`npm run dev` 或双击启动程序）中可用，线上 Sites 和 `npm start` 不提供本机文件同步。

### 首次连接

1. 在 [MyRobot 应用后台](https://open.feishu.cn/app/cli_aa03f00d80b89be9/baseinfo) 获取 App Secret；App ID 和知识库页面已预填。将密钥填写到网页的「连接配置」，点击「保存配置」。不需要在聊天中发送密钥。
2. 在应用的权限管理中开通 `wiki:wiki`、`docx:document`、`docx:document.block:convert`，创建并发布应用版本使权限生效。
3. 为应用授权目标知识库页面及子页面的阅读、编辑权限。**API 权限与文档资源权限是两回事**；参考[飞书知识库权限说明](https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/wiki-v2/wiki-qa)。只将机器人添加到聊天群不能替代文档授权。
4. 点击「测试连接」。成功说明可以读取目标节点，写入权限会在第一次推送时验证。

网页配置存储在项目根目录 `.feishu-local.json`，文件权限为 `0600`（Windows 权限语义依系统而异），并已加入 Git 忽略。密钥不会返回给浏览器、写入笔记索引或存入浏览器缓存。也可以在 `.env.local` 中设置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_WIKI_URL`；这些值优先于网页配置，启用后网页配置只读。修改环境配置需重启服务。

### 按钮行为

| 操作 | 效果 |
| --- | --- |
| 从飞书导入 | 读取所配置页面及其所有子页面，将新版文档放到本地 `飞书/` 目录，按页面原名和层级保存；仅同名时使用 `（2）`、`（3）` 等短编号，避免覆盖。节点 ID 单独保存在同步记录中。 |
| 选择笔记拉取 | 先列出知识库中尚未关联本地的新版文档，显示标题和完整目录，支持勾选、全选及查看原文。点击「拉取所选」后只下载所选正文，未勾选的父页面只保留目录；再次打开或刷新列表会排除已拉取的笔记。 |
| 推送当前笔记 | 本地每级文件夹对应飞书父文档，笔记在对应父文档下创建；以后更新同一篇文档并校正其父节点位置。只推送已保存正文，保留本地 YAML 标签等元数据。 |
| 推送整个当前文件夹 / 整个知识库 | 推送左侧当前选中的文件夹及全部子目录；根目录可推送整个知识库。已关联笔记更新原文，新笔记按本地目录层级创建父文档，复用已有飞书父页面；已关联笔记即使正文未改，也会校正位置。空文件夹同样创建父文档。 |
| 选择文件夹推送 | 在同步面板中勾选一个或多个文件夹，显示包含子目录的笔记数。重叠目录去重，已同步笔记跳过；单篇冲突或失败继续处理其余笔记，结束后逐篇列出结果。 |
| 拉取当前笔记 | 获取已关联文档的最新正文，保留本地 YAML 元数据。 |
| 另存为飞书新文档 | 创建新子页面并将当前笔记关联到新页面，原飞书文档保留，适合冲突后保留两份内容。 |

保存笔记不会触发飞书同步，也没有定时同步。不会自动传播文件删除、目录移动、文件重命名或标题变更；只有手动推送时才按本地层级调整飞书父子关系，移动父文档会携带其子页面。原文链接和正文保留，移动前记录备份，并核对移动结果。首次导入成功后，页面通过现有文件监视机制自动刷新。

飞书子页面删除后，在原知识库路径下重建同名新版文档，拉取、推送或再次导入会自动更新关联，继续使用原本地文件。正文与上次同步一致时可直接推送本地修改；重建后正文有变化时仍需先拉取，两端都有修改会保留冲突备份。只匹配原路径，不会关联其他目录的同名页面；同一路径存在多个同名页面、应用无法读取页面或上次推送尚未恢复时，会停止自动关联。若删除的是配置链接对应的知识库根页面，需要先更新配置链接。

支持文本、标题、粗体、斜体、链接、列表、待办、代码块、普通表格及图片。Markdown 与飞书排版并非逐字节往返：例如列表序号、空行会规范化。附件、提及、公式、评论、合并单元格及其他飞书专有内容不保证完整转换；导入会提示、保留原始文档块备份并禁止覆盖推送。超出 1000 个文档块的笔记需要拆分后推送。

导入时，文档读取与图片下载使用各自的共享限速队列；首次请求立即发送，后续只等待剩余限速时间。同一篇笔记最多同时下载 3 张图片，相同素材复用下载结果；本地图片写入仍按顺序进行，失败时等待已开始的下载结束，再报告错误，避免遗留后台写入。飞书返回限频时保留指数退避重试，目录和写入请求仍采用保守频率。

图片拉取后保存在笔记旁的 `笔记名.assets/` 目录，用相对路径显示，支持 PNG、JPEG、GIF、WebP、BMP（单张不超过 20 MB）。推送会读取知识库内的本地图片，创建图片块、上传素材并核对关联成功后，才移除旧正文；外链图片需先保存到本地再推送。编辑器调整尺寸或对齐后生成的 HTML `<img>` 会在推送时自动转换成 Markdown 图片，无须手动改写；本地 HTML、尺寸和对齐设置仍保留。代码示例及 HTML 注释中的图片标签不会上传。只修改图片文件而未修改 Markdown，也会识别为本地修改。素材读取或上传失败会报告错误并保留原有正文。图片下载及上传使用[素材下载](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/download)与[素材上传](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/upload_all)接口，应用需要对应素材权限及文档访问权限。

源同步块和引用同步块会展开为正文，包含其中的图片、列表和表格。引用块需要应用能够读取源文档。每次手动拉取都会重新读取源内容，即使当前文档版本号没有变化；读取不完整时保留本地已有正文。同步块在本地是内容快照，不会实时联动。单篇或文件夹覆盖推送前会弹出提醒，取消不推送；确认后，原文中的同步引用块可转换为普通文字和图片，更新同一个飞书页面，不再跟随源文档变化，源文档本身不会被修改或删除。原始文档块及本地正文会先备份。确认仅允许转换已完整读取的引用块；同步块源、读取不完整或其他不支持的内容仍保留保护，可另存为普通飞书文档。原先只有图片或同步块占位提示的笔记，重启服务后再次拉取即可补全，无须先编辑飞书原文。

### 冲突与恢复

- 本地和飞书都修改过时，拉取会提示选择「保留本地」或「用飞书覆盖本地」，并显示两份内容的备份位置。选择覆盖后还会弹出确认框；取消保留本地，确认则用飞书正文替换本地正文、保留 YAML 元数据并更新同步记录，飞书原文不变。覆盖前再次备份；如果提示后内容又变化，会要求重新确认。服务重启后旧确认失效，需要重新拉取。批量导入的冲突可以逐篇选择；也可以对照原文整理后另存为飞书新文档。
- 飞书发生任何版本变化时，覆盖推送会停止，先拉取处理。本地仍有修改但飞书未变时，拉取会跳过，允许推送本地内容。
- 笔记目录内的 `.zhixu-feishu/state.json` 保存对应关系、上次内容摘要及飞书版本号；`backups/*.json` 保存导入原始块、被替换内容及冲突两份内容。该目录不会被笔记索引或图片复制读取。备份包含笔记正文，请随笔记妥善保管。
- 推送先插入新内容，确认后再移除旧内容。飞书多接口操作不是事务：同步期间请不要在其他窗口编辑同一篇文档。系统会检查版本并尽量中止并发修改；无法保证外部编辑与删除请求之间的极小竞争窗口完全消失。
- 网络中断或部分写入失败后会保留 `pending` 记录并禁止自动重试，避免重复创建或误删。点击「检查并恢复操作」，系统会核对飞书版本号和所有文档块；只有与写入前完全一致时才解除保护，保留本地修改和原有备份。新文档创建、原文变化或部分写入仍需人工核对。对已有文档首次写入明确被权限拒绝时，不再留下锁定记录。不要直接删除整个状态文件或备份目录。
- 如果程序异常退出，确认没有同步进程运行后，可移除 `.zhixu-feishu/sync.lock` 释放锁；该锁与 `pending` 是独立保护，释放锁不表示未完成的文档写入已经恢复。
- 如果「另存为飞书新文档」中断，且原来已关联文档，面板会显示「取消另存为，恢复原文档关联」。点击即可自己恢复原来的关联，保留本地修改、同步基线及所有备份；不会修改或删除飞书里的原文、新副本。原文若有新修改，后续同步仍会提示冲突。

### 接口与验证

使用飞书官方的[节点解析](https://open.feishu.cn/document/server-docs/docs/wiki-v2/space-node/get_node)、[知识库节点创建](https://open.feishu.cn/document/server-docs/docs/wiki-v2/space-node/create)、[文档块读取](https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document-block/list)、[Markdown 转文档块](https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document/convert)、[嵌套块写入](https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document-block-descendant/create)接口。服务端使用应用身份的 `tenant_access_token`，缓存并刷新凭证，处理分页、限流与超时；不需要消息 Webhook 或公网回调。

`npm run test:feishu` 用隔离目录和模拟飞书响应验证同步、冲突、失败恢复保护和凭证隔离。它不会访问或修改实际飞书知识库；实际连通性与权限必须通过配置后的测试连接和一篇笔记的推送/拉取验证。
